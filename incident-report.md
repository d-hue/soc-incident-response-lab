# SOC Incident Investigation Report

## 1. Executive Summary

A simulated Windows endpoint was investigated following the execution of a suspicious executable, `ckjg.exe`.

Using Sysmon telemetry and Windows Event Viewer, I reconstructed the activity timeline and identified several indicators associated with potentially malicious behavior:

* An executable downloaded from an external HTTP URL
* Execution of the executable from a user's Downloads directory
* Creation of a file within the Windows Startup directory
* DNS resolution of a suspicious domain
* Outbound TCP communication to an external IP address and non-standard port
* Correlation between the suspicious process, DNS activity, and network communication

The investigation demonstrates a basic endpoint-focused SOC workflow involving event correlation, process analysis, persistence identification, DNS analysis, network investigation, and incident timeline reconstruction.

## 3. Initial Suspicious Activity

The investigation identified the executable:

`ckjg.exe`

The process was executed from:

`C:\Users\sarah.miller\Downloads\ckjg.exe`

Executing an unfamiliar executable directly from a user's Downloads directory was treated as suspicious and investigated further.

## 4. Initial Download Source

Sysmon Event ID 15 identified Zone.Identifier metadata associated with the downloaded executable.

The recorded originating URL was:

`http://gettsveriff.com/bgj3/ckjg.exe`

The executable was downloaded using Chrome.

This provided the initial entry point for the investigation.

**Evidence:**
[`04-download-url.png`](screenshots/04-download-url.png)

## 5. Persistence Activity

Sysmon Event ID 11 showed that `ckjg.exe` created the following file:

`C:\Users\sarah.miller\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\DeleteApp.url`

The Startup directory was significant because files placed in this location can be used to execute or trigger activity when a user logs into Windows.

This activity was therefore assessed as a **potential persistence mechanism**.

**Evidence:**
[`02-persistence.png`](screenshots/02-persistence.png)

---

## 6. DNS Investigation

Sysmon Event ID 22 showed that `ckjg.exe` queried the following domain:

`hkfasfsafg.click`

The domain resolved to:

`193.46.217.4`

The fact that the same suspicious executable generated the DNS request provided an important correlation between the endpoint process and the external infrastructure.

---

## 7. Command-and-Control Communication

Sysmon Event ID 3 identified an outbound TCP connection generated by:

`C:\Users\sarah.miller\Downloads\ckjg.exe`

The destination was:

`193.46.217.4:7777`

The destination IP matched the IP address returned by the previous DNS query.

This correlation significantly increased the confidence that the network activity was associated with the suspicious executable.

## 10. Analyst Assessment

The evidence indicates a potentially malicious execution chain beginning with the download of `ckjg.exe`.

Multiple independent Sysmon events were correlated to establish the sequence of activity:

**Download → Execution → Persistence → DNS Resolution → Network Communication**

The use of a user Downloads directory, creation of a Startup file, resolution of a suspicious domain, and outbound communication to the corresponding IP address were all treated as indicators requiring investigation.

The evidence supports classifying the activity as a **potential malware infection with possible persistence and command-and-control communication** within the simulated environment.

---

## 11. Recommended Response Actions

If this were a production environment, recommended actions would include:

1. Isolate the affected endpoint from the network.
2. Preserve relevant logs and forensic evidence.
3. Block the identified malicious domain and IP address where appropriate.
4. Remove the malicious executable and persistence mechanism after evidence preservation.
5. Search other endpoints for the identified indicators of compromise.
6. Review authentication and network activity associated with the affected user.
7. Determine whether additional payloads or post-compromise activity occurred.
8. Document and escalate the incident according to organizational incident-response procedures.
